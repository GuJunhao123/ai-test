#### 系统优化

##### Redis缓存优化

1. 配置CacheConfig

```
return RedisCacheManager.builder(connectionFactory).cacheDefaults(defaultConfig).withCacheConfiguration(CacheConstant.MODEL_PRICING_CACHE_NAME, modelPricingConfig).build();
```

​	CacheManager管理多个cache，cacheDefaults为通用配置，withCacheConfiguration为模型价格缓存独立配置。

​	CacheManager代表缓存系统，cache为缓存区（一个项目中可以有多个不同的缓存区，指定不同的配置），key指向不同的缓存数据。

2. 缓存使用@Cacheable

​	在需要进行缓存查询的方法前加注解@Cacheable，并指定缓存区和key，spring会自动先缓存查询，无结果再进行方法，并将返回值写入缓存，仅使用注解即可完成缓存逻辑，并解耦业务和缓存代码。

此处Redis所写配置注解实现的是Spring Cache 这个通用层，故其他缓存也适用。



##### 消息队列优化

增加消息持久化功能，队列优先级功能。实现起来很简单，更改配置即可。

在RabbitMQConfig中更改队列配置，支持消息持久化，以及优先级配置。注意要删除旧队列。

```
Map<String, Object> args = new HashMap<>();
args.put("x-max-priority", RabbitMQConstant.QUEUE_MAX_PRIORITY);
args.put("x-max-length", RabbitMQConstant.QUEUE_MAX_LENGTH);
return new Queue(RabbitMQConstant.TEST_QUEUE, true, false, false, args);
```

在批量测试方法中，配置postProcessor，设置优先级，以及持久化模式。

```
MessagePostProcessor postProcessor = msg -> {
    msg.getMessageProperties().setPriority(priority);
    msg.getMessageProperties().setDeliveryMode(MessageDeliveryMode.PERSISTENT);
    return msg;
};
```

在 rabbitTemplate.convertAndSend() 方法中附带postProcessor参数即可。



##### 流量控制

选择redisson：简单易用，令牌桶算法适用，分布式操作成熟。分布式限流，多个服务实例共享一个限流器。

使用redisson：

1. 创建RedissonConfig，初始化RedissonClient
2. 创建RateLimit注解，RateLimitAspect切面（核心，生成特定Key，创建限流器，选择性限流）
3. 登录界面使用IP限流，核心方法使用USER限流，负荷大的方法使用API限流

一个Key，一个限流器，一个令牌桶。

RateLimitAspect切面阻塞方法执行，这里通过未获取令牌而抛异常，来中断方法调用。

buildKey() 构建的key要有当前方法名标识，否则会出现多个方法共用一个限流器的问题，令牌桶的设置也会混乱。



##### SSE错误友好返回

AI调用中前端接收的是text/event-stream格式数据，而后端传递的JSON报错信息不匹配，故更改后端为SSE报错格式。

实现：

1. GlobalExceptionHandler添加SSE格式请求检验，并构建SSE出错格式的Response直接发送给客户端
2. 前端新增SSE出错事件处理



完整限流处理：接口挂限流注解，方法调用前，AOP创建限流器获取令牌，令牌获取成功，方法调用；令牌获取失败，抛异常，方法停止，全局异常捕获，检查request的SSE请求格式，返回SSE报错信息。
